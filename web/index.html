Fetch. Check. Read.

Ferrotype starts from a block hash you already trust. Everything under it is recomputed from bytes any node can hand you.

01

Fetch

The block header from eth_getBlockByNumber and the account and storage proofs from eth_getProof, from any node. The bytes are checked, never believed.

02

Check

The header must hash to the block hash. Every node must hash to the 32-byte reference its parent holds, from the state root down, and the account leads to its storage root.

03

Read

The slot’s value, or a proof that it is empty: a branch with nothing in the slot the key asks for, or a leaf that holds another key.

One verifier, three runtimes.

The same Fe library builds into a contract, a native command-line tool and the WebAssembly module that checked the read above.

Soundness

An early stop is not a zero.

Lido’s verifier accepts a proof whose node list stops early after a branch node and reads the slot as zero. Roman Agureev (Curve) found this class of bug in March 2025 and ChainSecurity coordinated its disclosure; Curve’s patched copy rejects it, and so does Ferrotype.

ChainSecurity’s write-up

Governance by any ERC-20, counted at a past block.

Plebiscite is a treasury whose vote weight is the voter’s balance at the proposal’s block, read from the token’s own storage. USDC has no checkpoints and needs none.

Rules, all tested
  • Tokens moved after the snapshot don’t count twice.
  • A USDC-blacklisted holder can’t vote.
  • A second vote is refused.
  • Someone else’s proof is refused.
  • A proposer needs a share of the supply at the snapshot.
  • Execution waits out a timelock, then expires.
  • Only Execute can move treasury funds.
Vote { id, support, balance_proof } -> u256 uses (ctx, layout_kind, balance_slot, mut ledger, mut log)
Execute { id, data } -> bool uses (ctx, mut call, quorum_bps, timelock, grace, mut ledger, mut log)
Each message names the effects it may use. No other message lists call, so only Execute can move funds.
