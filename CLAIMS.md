# Claims and their evidence

Every claim in the README and on the demo page, with how strong its evidence is and how to reproduce it.

- **REPRODUCIBLE**: a command in this repository produces it, on any machine.
- **VERIFIED-LIVE**: it can be checked against a public chain right now.
- **NOT CLAIMED**: listed below so that no one reads more into the work than it shows.

| Claim | Evidence | Reproduce |
|---|---|---|
| The verifier proves presence and absence and rejects invalid proofs with the right reason, on 335 vectors generated by the reference implementation `@ethereumjs/trie` | REPRODUCIBLE | `fe test ingots/conformance`; vectors from `node scripts/vectors/gen.mjs` (byte-identical on every run) |
| The mainnet reads and the generated vectors get the same verdicts on the EVM, natively and as WebAssembly; the contract tests run on the EVM only, the fuzz verdicts are compared between the EVM and native builds, and the README says what each target runs | REPRODUCIBLE | `fe test ingots/conformance`, `fe test --backend native ingots/conformance`, `node wasm/check.mjs` |
| The EVM and native builds reach the same verdict on every damaged proof of the first 300 fuzzing rounds | REPRODUCIBLE | test `every_target_reaches_the_same_300_verdicts` in `ingots/conformance/src/fuzz.fe`, run by both commands above |
| Of 1,000,000 damaged mainnet proofs none proves a wrong value, and the verifier never panics | REPRODUCIBLE | `target/fuzz/fuzz 1000000 1` (after `scripts/build.sh`) |
| One read costs about half what Lido's audited verifier spends and a third of Optimism's, on the same proofs (exact figures in the README's gas table) | REPRODUCIBLE | `cd bench && forge test && python3 render.py` → `bench/results/gas.md` |
| Optimism's `MerkleTrie` cannot prove an empty slot or a missing account | REPRODUCIBLE | the same benchmark; the revert reasons are in `bench/results/gas.json` |
| Lido's verifier accepts a proof whose node list stops early after a branch node, reading the slot as zero; Curve's patched verifier, Optimism's and Ferrotype reject it. This reproduces a publicly disclosed bug class (Roman Agureev, Curve, March 2025; [ChainSecurity's write-up](https://www.chainsecurity.com/blog/when-empty-means-valid-exploiting-mpt-proof-verification-for-an-alternative-truth)); it is not a new finding | REPRODUCIBLE | `test_rejectsInvalidProofs` in `bench/test/StorageProofBench.t.sol` → `bench/results/soundness.json` |
| `@ethereumjs/trie`'s `verifyProof` accepts 12 of the 20 structurally malformed vectors, 2 of the 8 bad references and all 21 proofs with unused nodes | REPRODUCIBLE | `node scripts/vectors/gen.mjs` prints these counts under `ejs` |
| Branch decoding in one pass saved 47% of the gas; `-O 2` saves 0.5%; unchecked arithmetic would save 1.0% | REPRODUCIBLE | rebuild at the commit before `Decode branch nodes in one pass` and rerun the benchmark; build with `-O 1`; add `#[arithmetic(unchecked)]` to `rlp::item_at` and `rlp::branch_child` |
| Token balances are read with the token's own layout: Solidity mappings (USDC, with its flag bit) and Vyper mappings (CRV, `keccak(slot . key)`), each proven on a real mainnet proof and equal to `balanceOf` at the same block | REPRODUCIBLE | tests `usdc_balance_*` and `crv_*` in `ingots/conformance/src/tests.fe`; live: `ferrotype balance --layout vyper --slot 3 --token 0xD533a949740bb3306d119CC777fa900bA034cd52 --holder 0xF977814e90dA44bFA03b6295A0616a897441aceC --rpc <mainnet RPC>` |
| The library has no `unsafe` code | REPRODUCIBLE | `grep -rn unsafe ingots/ferrotype/src` finds nothing |
| The empty trie root and empty code hash are computed by the compiler and checked against the published values | REPRODUCIBLE | `static_assert` in `trie.fe` and `state.fe`; change either reference value and the build fails |
| The CLI reads live mainnet and Sepolia state, checking the header hash and both proofs before printing | VERIFIED-LIVE | `target/bin/ferrotype read/balance --rpc <any Ethereum RPC>` |
| The CLI handles Amsterdam headers (EIP-7928 block access list hash, EIP-7843 slot number) | VERIFIED-LIVE | the same commands with a Sepolia RPC |
| The governance flow works end to end: proposals anchored to a real block hash, snapshot balances, refusals, treasury execution | REPRODUCIBLE | `anvil & RPC=http://127.0.0.1:8545 scripts/e2e.sh` |
| Only `Execute` can move treasury funds: the one outgoing call is `pay`, which takes `call: mut Call`, and no other arm can reach it | REPRODUCIBLE | call `pay` from `Vote`, or remove `call` from `Execute`'s `uses` clause: `missing effect Call required by pay` |
| Fe 26.6 does not check the `mut` marker of a contract-level effect inside a `recv` arm | REPRODUCIBLE | the minimal reproduction in [argotorg/fe#2047](https://github.com/argotorg/fe/issues/2047); Ferrotype's arms never call `call` themselves |
| The contracts run on Sepolia: one proposal opened against a remembered block hash, three votes weighted by snapshot balances (700 for, 300 against while today's balances are 100 and 600), then executed by the treasury | VERIFIED-LIVE | the transactions listed in the README's "Live on Sepolia" section; `cast call <PlebisciteDemo> "tally(uint256)(uint256,uint256,uint256,uint256,uint256,bool)" 1` |
| The deployed contracts answer with no funds: `StateReader` checks a mainnet proof against its state root, and `votingPower` returns a holder's snapshot balance from a saved proof and refuses someone else's proof (`InvalidProof(2)`, HashMismatch) | VERIFIED-LIVE | `eth_call` with the proofs in `fixtures/mainnet` and `deployments/sepolia-snapshots.json` |
| The native CLI accepts every saved mainnet proof and refuses each damaged copy (a flipped bit, a missing node, a changed state root) with the reason it prints | REPRODUCIBLE | `scripts/record_cli_runs.py`; its output for every file is in `web/public/runs/index.json` |
| The CLI's calldata matches the contracts' ABI | REPRODUCIBLE | it is encoded from the contracts' `msg` types; the end-to-end run sends it to the contracts |

## Local versus real

| Piece | Real or local |
|---|---|
| Mainnet fixtures in `fixtures/mainnet` | Real `eth_getProof` and `eth_getBlockByNumber` answers from Ethereum mainnet, saved by `scripts/fetch_proof.py` |
| Synthetic vectors in `fixtures/synthetic` | Generated tries and proofs from the reference implementation, deterministic |
| `DemoToken` | A plain ERC-20 written for the local end-to-end run; `Plebiscite` reads it exactly as it reads any token |
| The end-to-end chain | A local anvil node: real headers, real block hashes, real state roots and proofs, local time travel |
| Gas numbers | Foundry measurements of the deployed bytecode of each verifier, on the real mainnet proofs |

## Not claimed

- That Ferrotype or Plebiscite is audited or ready for production. Fe 26 is not production-ready.
- That `Plebiscite`'s economic design (quorum, snapshot age, one call per proposal) suits a real treasury.
- That every token's storage layout is supported: rebasing tokens and custom layouts are not.
- That the CLI signs or sends transactions: it prints calldata for a wallet or `cast` to send.
- Anything about deployed contracts that use the Lido or Optimism verifiers, or a new vulnerability: the early-ending-proof behaviour was found and disclosed by others in 2025, and the benchmark only measures the libraries on fixed inputs.
- Gas figures for proofs other than the five reads in `bench/`; trie depth changes them.
